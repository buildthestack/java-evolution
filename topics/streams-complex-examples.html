1 · groupingBy — from simple to multi-level

groupingBy builds a Map from a classifier function. Pair it with a downstream collector to aggregate, count, or nest further.

1.1 · Simple grouping — list per key

// employees by department
Map<String, List<Employee>> byDept =
    emps.stream().collect(groupingBy(Employee::dept));
// {Engineering=[Ada, Bob, Grace], Sales=[Cy, Dee], HR=[Eve, Frank]}

1.2 · Count per group

Map<String, Long> countByDept =
    emps.stream().collect(groupingBy(Employee::dept, counting()));
// {Engineering=3, Sales=2, HR=2}

1.3 · Sum / average per group

// total salary budget per dept
Map<String, Double> budgetByDept =
    emps.stream().collect(groupingBy(Employee::dept, summingDouble(Employee::salary)));
// {Engineering=310000.0, Sales=130000.0, HR=145000.0}

// average salary per dept
Map<String, Double> avgByDept =
    emps.stream().collect(groupingBy(Employee::dept, averagingDouble(Employee::salary)));
// {Engineering=103333.33..., Sales=65000.0, HR=72500.0}

1.4 · Highest earner per department (downstream: maxBy)

Map<String, Optional<Employee>> topEarner = emps.stream()
    .collect(groupingBy(Employee::dept,
             maxBy(Comparator.comparingDouble(Employee::salary))));
// Engineering → Optional[Bob(110000)], Sales → Optional[Dee(68000)], HR → Optional[Eve(74000)]

// unwrap the Optional using collectingAndThen
Map<String, Employee> topEarnerUnwrapped = emps.stream()
    .collect(groupingBy(Employee::dept,
             collectingAndThen(maxBy(Comparator.comparingDouble(Employee::salary)),
                               Optional::get)));
// Engineering=Bob, Sales=Dee, HR=Eve

1.5 · Multi-level grouping (dept → city → names)

Nest one groupingBy inside another, adding a mapping downstream to get names only.

Map<String, Map<String, List<String>>> deptCityNames = emps.stream()
    .collect(groupingBy(Employee::dept,
             groupingBy(Employee::city,
             mapping(Employee::name, toList()))));
// {
//   Engineering={NYC=[Ada, Grace], SF=[Bob]},
//   Sales={NYC=[Cy], SF=[Dee]},
//   HR={NYC=[Eve], SF=[Frank]}
// }

1.6 · Sorted result map (TreeMap)

// sorted department keys, each list sorted by salary descending
Map<String, List<String>> sortedNames = emps.stream()
    .collect(groupingBy(Employee::dept, TreeMap::new,
             collectingAndThen(
                 toList(),
                 list -> list.stream()
                     .sorted(Comparator.comparingDouble(Employee::salary).reversed())
                     .map(Employee::name)
                     .toList())));
// Engineering=[Bob, Grace, Ada], HR=[Eve, Frank], Sales=[Dee, Cy]  (keys sorted A-Z)

1.7 · Group by derived key (salary band)

Map<String, List<String>> byBand = emps.stream()
    .collect(groupingBy(
        e -> switch ((int)(e.salary() / 25_000)) {
            case 0, 1, 2 -> "< 75k";
            case 3       -> "75k–99k";
            default      -> "100k+";
        },
        mapping(Employee::name, toList())));
// {< 75k=[Cy, Dee, Eve, Frank], 100k+=[Ada, Bob, Grace]}

1.8 · Orders: revenue per category, paid only

Map<String, Double> paidRevByCategory = orders.stream()
    .filter(Order::paid)
    .collect(groupingBy(Order::category, summingDouble(Order::amount)));
// {Electronics=1200.0, Clothing=570.0, Books=125.0}

2 · partitioningBy — split by predicate

partitioningBy always returns a Map<Boolean, …> with both keys guaranteed — even if one group is empty.

2.1 · Active vs inactive employees

Map<Boolean, List<Employee>> activeMap =
    emps.stream().collect(partitioningBy(Employee::active));
List<Employee> active   = activeMap.get(true);   // [Ada, Bob, Cy, Eve, Frank]
List<Employee> inactive = activeMap.get(false);  // [Dee, Grace]

2.2 · Partition + downstream (count per bucket)

Map<Boolean, Long> countByActive =
    emps.stream().collect(partitioningBy(Employee::active, counting()));
// {false=2, true=5}

2.3 · Partition high earners, collect their names

Map<Boolean, List<String>> earnerNames = emps.stream()
    .collect(partitioningBy(
        e -> e.salary() >= 90_000,
        mapping(Employee::name, toList())));
// {false=[Cy, Dee, Eve, Frank], true=[Ada, Bob, Grace]}

2.4 · Paid vs unpaid orders, summed

Map<Boolean, Double> revenueByPayment = orders.stream()
    .collect(partitioningBy(Order::paid, summingDouble(Order::amount)));
// {false=3990.0, true=1895.0}

3 · teeing — two aggregations, one pass Java 12

Collectors.teeing(c1, c2, merger) feeds every element into two independent sub-collectors simultaneously and merges their results — no second traversal.

3.1 · Sum + count → average (without two passes)

Two passes — wasteful
double sum   = emps.stream().mapToDouble(Employee::salary).sum();
long   count = emps.stream().count();
double avg   = sum / count;
teeing — single pass
double avg = emps.stream().collect(teeing(
    summingDouble(Employee::salary),
    counting(),
    (sum, count) -> sum / count));
// 83571.42...

3.2 · Min + max salary in one pass

record SalaryRange(double min, double max) {}

SalaryRange range = emps.stream().collect(teeing(
    minBy(Comparator.comparingDouble(Employee::salary)),
    maxBy(Comparator.comparingDouble(Employee::salary)),
    (minE, maxE) -> new SalaryRange(
        minE.map(Employee::salary).orElse(0.0),
        maxE.map(Employee::salary).orElse(0.0))));
// SalaryRange[min=62000.0, max=110000.0]

3.3 · Split + aggregate simultaneously

// active employees: (names list) AND (total salary budget) — one pass
record ActiveReport(List<String> names, double totalBudget) {}

ActiveReport report = emps.stream()
    .filter(Employee::active)
    .collect(teeing(
        mapping(Employee::name, toList()),
        summingDouble(Employee::salary),
        ActiveReport::new));
// ActiveReport[names=[Ada, Bob, Cy, Eve, Frank], totalBudget=512000.0]

3.4 · Order stats: paid revenue + unpaid count

record OrderSummary(double paidRevenue, long unpaidCount) {}

OrderSummary summary = orders.stream().collect(teeing(
    // downstream 1: filter paid, sum amounts
    collectingAndThen(
        filtering(Order::paid, summingDouble(Order::amount)),
        d -> d),
    // downstream 2: filter unpaid, count
    filtering(Predicate.not(Order::paid), counting()),
    OrderSummary::new));
// OrderSummary[paidRevenue=1895.0, unpaidCount=2]
Collectors.filtering (Java 9) lets you push a predicate inside a downstream collector so the filtering is scoped to that branch, not the whole stream.

4 · reduce — beyond simple sums

Use reduce when no built-in collector fits — building a product, concatenating strings under rules, or accumulating a result whose type differs from the element type.

4.1 · Product of a list (multiply all elements)

int product = Stream.of(1, 2, 3, 4, 5).reduce(1, (a, b) -> a * b);
// 120

4.2 · Longest string

Optional<String> longest = Stream.of("Java", "Streams", "are", "powerful")
    .reduce((a, b) -> a.length() >= b.length() ? a : b);
// Optional[Streams]

4.3 · 3-arg reduce: String stream → total char count (U ≠ T)

int totalChars = Stream.of("hello", "world", "stream")
    .reduce(
        0,                                      // identity (int)
        (count, word) -> count + word.length(), // accumulator: (int, String) -> int
        Integer::sum);                          // combiner: merges partial sums (parallel)
// 16

4.4 · Build a summary map via reduce (merge maps)

// count tag frequency across all products
Map<String, Integer> tagCount = products.stream()
    .flatMap(p -> p.tags().stream())
    .reduce(
        new HashMap<>(),
        (map, tag) -> { var m = new HashMap<>(map); m.merge(tag, 1, Integer::sum); return m; },
        (a, b) -> { var m = new HashMap<>(a); b.forEach((k,v) -> m.merge(k,v,Integer::sum)); return m; }
    );
// {tech=3, premium=2, casual=2, work=1, summer=1, education=1, denim=1, fiction=1, leisure=1}
For frequency counting, groupingBy(identity(), counting()) (see §5.5) is cleaner than a map-merge reduce — prefer reduce only when no Collector fits.

4.5 · Immutable string accumulation under a budget

// keep prepending names as long as total salary <= 300_000
String under300k = emps.stream()
    .sorted(Comparator.comparingDouble(Employee::salary))
    .reduce(
        "",
        (acc, e) -> {
            double current = acc.isEmpty() ? 0 :
                emps.stream().filter(x -> acc.contains(x.name())).mapToDouble(Employee::salary).sum();
            return current + e.salary() <= 300_000 ? (acc.isEmpty() ? e.name() : acc + ", " + e.name()) : acc;
        },
        (a, b) -> a.isEmpty() ? b : a   // combiner (sequential: never called)
    );
// Cy, Dee, Eve, Frank, Ada

5 · Collectors: toMap, joining, downstream

5.1 · toMap — build a lookup map

// employee name → salary lookup
Map<String, Double> salaryLookup =
    emps.stream().collect(toMap(Employee::name, Employee::salary));

// handle collisions: keep the higher salary when names clash (hypothetical)
Map<String, Double> maxSalaryByName =
    emps.stream().collect(toMap(Employee::name, Employee::salary, Double::max));

5.2 · toMap — object → object lookup

// orderId → order object for fast lookup

    orders.stream().collect(toMap(Order::orderId, o -> o));

// category → most expensive order in that category
Map<String, Order> topOrderByCategory = orders.stream()
    .collect(toMap(
        Order::category,
        o -> o,
        (existing, candidate) -> existing.amount() >= candidate.amount() ? existing : candidate));

// simple CSV of active employee names
String csv = emps.stream()
    .filter(Employee::active)
    .map(Employee::name)
    .sorted()
    .collect(joining(", "));
// Ada, Bob, Cy, Eve, Frank

// with prefix + suffix
String report = emps.stream()
    .filter(e -> e.dept().equals("Engineering"))

DoubleSummaryStatistics salaryStats =

6 · Custom Collector

Use Collector.of(supplier, accumulator, combiner, finisher) when no built-in collector fits your aggregation.

6.1 · Running total → list of cumulative sums

// running cumulative salary total as you iterate employees sorted by salary
Collector<Employee, ?, List<Double>> runningTotal = Collector.of(
    () -> new double[]{0},                               // supplier: mutable accumulator
    (acc, e) -> acc[0] += e.salary(),                    // accumulator: add salary
    (a, b) -> new double[]{a[0] + b[0]},                 // combiner (parallel)
    acc -> List.of(acc[0])                               // finisher (simplified)
);
// For a real running-total list, use a proper state object:
record RunningAcc(List<Double> sums, double running) {
    RunningAcc add(double v) {
        List<Double> next = new ArrayList<>(sums);
        next.add(running + v);
        return new RunningAcc(next, running + v);
    }
}
List<Double> cumulativeSalaries = emps.stream()
    .sorted(Comparator.comparingDouble(Employee::salary))
    .collect(Collector.of(
        () -> new ArrayList<Double[]>() {{ add(new Double[]{0.0}); }},
        (list, e) -> {
            double prev = list.get(list.size() - 1)[0];
            list.add(new Double[]{prev + e.salary()});
        },
        (a, b) -> { a.addAll(b.subList(1, b.size())); return a; },
        list -> list.stream().skip(1).map(d -> d[0]).toList()
    ));
// [62000.0, 130000.0, 201000.0, 272000.0, 367000.0, 477000.0, 585000.0]

6.2 · Top-N collector (keep only top 3 by salary)

import java.util.TreeMap;
import java.util.stream.Collector;

static <T> Collector<T, ?, List<T>> topN(int n, Comparator<T> cmp) {
    return Collector.of(
        () -> new TreeSet<>(cmp),                  // min-heap via TreeSet
        (set, item) -> {
            set.add(item);
            if (set.size() > n) set.pollFirst();   // evict the smallest
        },
        (a, b) -> { a.addAll(b); while (a.size() > n) a.pollFirst(); return a; },
        set -> set.stream().sorted(cmp.reversed()).toList()
    );
}

// Usage
List<Employee> top3 = emps.stream()
    .collect(topN(3, Comparator.comparingDouble(Employee::salary)));
// [Bob(110000), Grace(105000), Ada(95000)]

6.3 · Histogram collector (group into fixed-width buckets)

Collector<Employee, ?, Map<String, Long>> salaryHistogram =
    groupingBy(e -> {
        long bucket = (long)(e.salary() / 25_000) * 25_000;
        return bucket + "–" + (bucket + 25_000);
    }, TreeMap::new, counting());

Map<String, Long> histogram = emps.stream().collect(salaryHistogram);
// {50000–75000=2, 75000–100000=3, 100000–125000=2}

8 · flatMap — flattening nested structures

flatMap turns each element into a stream and merges them — the go-to for nested collections, optional values, and splitting strings.

8.1 · Flatten nested lists

// all tags from all products (flat list)
List<String> allTags = products.stream()
    .flatMap(p -> p.tags().stream())
    .toList();
// [tech, premium, work, casual, summer, tech, education, tech, premium, casual, denim, fiction, leisure]

// distinct tags only
List<String> uniqueTags = products.stream()
    .flatMap(p -> p.tags().stream())
    .distinct()
    .sorted()
    .toList();
// [casual, denim, education, fiction, leisure, premium, summer, tech, work]

8.2 · Products that have a specific tag

// find all products tagged "tech"
List<String> techProducts = products.stream()
    .filter(p -> p.tags().contains("tech"))
    .map(Product::name)
    .toList();
// [Laptop, Java Book, Phone]

List<String> sentences = List.of(

// unique words, sorted

8.4 · Cartesian product (all pairs)

List<String> depts  = List.of("Engineering", "Sales", "HR");
List<String> cities = List.of("NYC", "SF");

8.5 · flatMap with Optional (unwrap present values)

List<Optional<String>> optNames = List.of(

8.6 · mapMulti — imperative alternative to flatMap (Java 16)

// repeat each tag once for each product it appears on (same as flatMap, but zero allocation per element)

9 · Optional — null-safe stream chains

Optional is not a collection, but it integrates cleanly with streams — especially via Optional.stream() (Java 9) and ifPresentOrElse (Java 9).

9.1 · findFirst / findAny → safe downstream processing

// find first Engineering employee earning over 100k
Optional<Employee> topEng = emps.stream()
    .filter(e -> e.dept().equals("Engineering") && e.salary() > 100_000)
    .findFirst();

// safe extraction chain — never NPE
String topEngName = topEng.map(Employee::name).orElse("none");
// "Bob"

// ifPresentOrElse (Java 9) — side-effecting alternatives
topEng.ifPresentOrElse(
    e -> System.out.println("Top eng: " + e.name()),
    () -> System.out.println("No match"));
// "Top eng: Bob"

9.2 · Optional.or — fallback chain (Java 9)

// look in Engineering, fall back to HR, fall back to "Unknown"
String name = emps.stream()
    .filter(e -> e.dept().equals("Engineering") && e.salary() > 200_000)
    .findFirst()                                               // Optional.empty()
    .or(() -> emps.stream()
        .filter(e -> e.dept().equals("HR") && e.salary() > 200_000)
        .findFirst())                                          // Optional.empty()
    .map(Employee::name)
    .orElse("Unknown");
// "Unknown"

9.3 · flatMap on Optional (chain of lookups)

Map<String, Employee> byName =
    emps.stream().collect(toMap(Employee::name, e -> e));

// lookup chain: Eve → her department head (first member of her dept with highest salary)
Optional<String> deptHead = Optional.ofNullable(byName.get("Eve"))
    .map(Employee::dept)
    .flatMap(dept -> emps.stream()
        .filter(e -> e.dept().equals(dept))
        .max(Comparator.comparingDouble(Employee::salary)))
    .map(Employee::name);
// Optional[Eve]   (Eve is the highest earner in HR at 74000)

9.4 · Filter nulls from a stream using Optional

List<String> rawNames = Arrays.asList("Ada", null, "Bob", null, "Cy");

// Option A: filter(Objects::nonNull) — simplest
List<String> clean1 = rawNames.stream()
    .filter(Objects::nonNull)
    .toList();

// Option B: flatMap via Optional.ofNullable (unwraps non-null, drops null)
List<String> clean2 = rawNames.stream()
    .flatMap(n -> Optional.ofNullable(n).stream())
    .toList();
// both → [Ada, Bob, Cy]

9.5 · Collect to Optional — empty stream guard

// sum salaries only if there are any Engineering employees (guard against empty)
OptionalDouble engAvg = emps.stream()
    .filter(e -> e.dept().equals("Engineering"))
    .mapToDouble(Employee::salary)
    .average();   // returns OptionalDouble — empty if no elements

double result = engAvg.orElseThrow(() -> new IllegalStateException("No engineers"));
// 103333.33...

10 · Kitchen-sink: combining everything

Each example below is a self-contained, runnable pipeline that chains multiple techniques.

10.1 · Payroll report — group, aggregate, sort, format

// dept → "DEPT: N employees, avg $X, top earner: Name"
String payrollReport = emps.stream()
    .collect(groupingBy(Employee::dept, TreeMap::new,
        teeing(
            counting(),
            teeing(
                averagingDouble(Employee::salary),
                collectingAndThen(maxBy(Comparator.comparingDouble(Employee::salary)),
                                  opt -> opt.map(Employee::name).orElse("-")),
                (avg, topName) -> String.format("avg $%,.0f, top: %s", avg, topName)
            ),
            (count, details) -> count + " employees, " + details
        )))
    .entrySet().stream()
    .map(e -> e.getKey().toUpperCase() + ": " + e.getValue())
    .collect(joining("\n"));

11 · Intermediate operations — complete patterns

Every intermediate op is lazy — it describes the pipeline but nothing runs until a terminal op pulls elements through. These patterns cover the ones most often misused or underused.

11.1 · filter — Predicate composition

Predicate's and, or, negate let you build reusable filter logic without repeating lambda bodies.

Predicate<Employee> isActive   = Employee::active;
Predicate<Employee> isHighPaid = e -> e.salary() >= 90_000;
Predicate<Employee> isNYC      = e -> e.city().equals("NYC");

// compose — active AND high-paid
List<String> activeHighPaid = emps.stream()
    .filter(isActive.and(isHighPaid))
    .map(Employee::name).toList();
// [Ada, Bob]

// negate — NOT active
List<String> inactive = emps.stream()
    .filter(isActive.negate())   // same as Predicate.not(Employee::active)
    .map(Employee::name).toList();
// [Dee, Grace]

// or — NYC OR high-paid
List<String> nycOrHighPaid = emps.stream()
    .filter(isNYC.or(isHighPaid))
    .map(Employee::name).distinct().toList();
// [Ada, Bob, Cy, Eve, Grace]

11.2 · distinct — de-duplicate by a field (not just equals)

distinct() uses equals — to deduplicate by a specific field, use a stateful predicate via a Set.

// one employee per city (first encountered)
Set<String> seen = ConcurrentHashMap.newKeySet();  // thread-safe for parallel()
List<Employee> onePerCity = emps.stream()
    .filter(e -> seen.add(e.city()))  // add returns false if already present
    .toList();
// [Ada(NYC), Bob(SF)]  — first employee encountered per city

// cleaner: collect to a map, then values (keeps first per key)
Map<String, Employee> firstPerCity = emps.stream()
    .collect(toMap(Employee::city, e -> e, (existing, dup) -> existing));
// NYC → Ada,  SF → Bob

11.3 · sorted — nullsFirst / nullsLast, reversed chains

// sort by city (nulls last), then salary descending
List<String> rawCities = Arrays.asList("NYC", null, "SF", null, "NYC");
List<String> sortedCities = rawCities.stream()
    .sorted(Comparator.nullsLast(Comparator.naturalOrder()))
    .toList();
// [NYC, NYC, SF, null, null]

// multi-key: dept A→Z, then salary desc, then name A→Z
List<Employee> ordered = emps.stream()
    .sorted(Comparator.comparing(Employee::dept)
        .thenComparing(Comparator.comparingDouble(Employee::salary).reversed())
        .thenComparing(Employee::name))
    .toList();
// Engineering: Bob(110k), Grace(105k), Ada(95k)
// HR: Eve(74k), Frank(71k)
// Sales: Dee(68k), Cy(62k)

11.4 · peek — pipeline debugging

peek is for inspection only — never use it for side effects you depend on, because lazy evaluation means it may not be called the way you expect.

List<String> result = emps.stream()
    .peek(e -> System.out.println("  before filter: " + e.name()))
    .filter(e -> e.salary() > 80_000)
    .peek(e -> System.out.println("  after  filter: " + e.name()))
    .map(Employee::name)
    .peek(n -> System.out.println("  after  map:    " + n))
    .toList();
// before filter: Ada
// after  filter: Ada
// after  map:    Ada
// before filter: Bob
// after  filter: Bob  ... etc.
// Shows the element-by-element pull model — not batch-then-batch

11.5 · limit + skip — pagination

int pageSize = 2;
int pageNum  = 1;   // 0-indexed

// page 0: [Ada, Bob],  page 1: [Cy, Dee],  page 2: [Eve, Frank], ...
List<String> page = emps.stream()
    .sorted(Comparator.comparing(Employee::name))
    .skip((long) pageNum * pageSize)
    .limit(pageSize)
    .map(Employee::name)
    .toList();
// [Cy, Dee]

// total pages
long total = emps.stream().count();
int  pages = (int) Math.ceil((double) total / pageSize);   // 4

11.6 · takeWhile + dropWhile Java 9

Unlike filter, these operate on a leading run — they stop (or start) at the first element that fails the predicate.

// stream already sorted by salary ascending
List<Employee> bySalary = emps.stream()
    .sorted(Comparator.comparingDouble(Employee::salary))
    .toList();
// [Cy(62k), Dee(68k), Eve(74k), Frank(71k), Ada(95k), Grace(105k), Bob(110k)]
// note: Frank(71k) is out of strict order relative to Eve(74k) after sort — they're equal

// takeWhile: keep elements while salary < 80k (stops at first failure)
List<String> under80k = bySalary.stream()
    .takeWhile(e -> e.salary() < 80_000)
    .map(Employee::name).toList();
// [Cy, Dee, Eve, Frank]  — stops at Ada (95k)

// dropWhile: skip elements while salary < 80k (starts emitting at first failure)
List<String> from80k = bySalary.stream()
    .dropWhile(e -> e.salary() < 80_000)
    .map(Employee::name).toList();
// [Ada, Grace, Bob]
takeWhile/dropWhile only work correctly on a stream that is already ordered by the same key you are testing. On an unordered stream, the cut point is arbitrary.

11.7 · Stream.iterate — bounded infinite sequence Java 9 (3-arg)

// Java 8: 2-arg — infinite, must limit()
List<Integer> powersOf2 = Stream.iterate(1, n -> n * 2)
    .limit(8)
    .toList();
// [1, 2, 4, 8, 16, 32, 64, 128]

// Java 9: 3-arg — built-in termination predicate, no limit() needed
List<Integer> under1000 = Stream.iterate(1, n -> n < 1000, n -> n * 2)
    .toList();
// [1, 2, 4, 8, 16, 32, 64, 128, 256, 512]

// generate working-day dates for next 5 business days
LocalDate today = LocalDate.now();
List<LocalDate> bizDays = Stream.iterate(today.plusDays(1), d -> d.plusDays(1))
    .filter(d -> d.getDayOfWeek() != DayOfWeek.SATURDAY
              && d.getDayOfWeek() != DayOfWeek.SUNDAY)
    .limit(5)
    .toList();

11.9 · Stream.concat — merge two streams

List<Employee> nyc = emps.stream().filter(e -> e.city().equals("NYC")).toList();
List<Employee> sf  = emps.stream().filter(e -> e.city().equals("SF")).toList();

// merge and de-duplicate names
List<String> allNames = Stream.concat(nyc.stream(), sf.stream())
    .map(Employee::name)
    .distinct()
    .sorted()
    .toList();
// [Ada, Bob, Cy, Dee, Eve, Frank, Grace]

// concat three or more: nest concat calls
Stream<String> three = Stream.concat(
    Stream.concat(Stream.of("a", "b"), Stream.of("c", "d")),
    Stream.of("e", "f"));
// a, b, c, d, e, f
For more than two streams use Stream.of(s1, s2, s3).flatMap(s -> s) instead of deeply nested concat.

11.10 · unordered — unlock parallel optimisations

// when encounter order doesn't matter, unordered() lets parallel avoid order-maintenance overhead
long count = emps.parallelStream()
    .unordered()
    .filter(e -> e.salary() > 70_000)
    .count();
// same result — faster on large streams because parallel chunks don't need to merge in order

12 · Numeric & primitive streams

IntStream, LongStream, DoubleStream eliminate boxing overhead and add numeric-only operations: sum, average, summaryStatistics, and closed-range generation.

12.1 · IntStream.range / rangeClosed — index-based loops

// sum 1 to 100

    .map(i -> i * i)
    .boxed()
    .toList();

// index + element (zip index into stream)

    .mapToObj(i -> (i + 1) + ". " + emps.get(i).name())
    .toList();

13 · Advanced collector patterns

13.1 · Collectors.flatMapping Java 9

flatMapping is a downstream collector — it lets you flatMap inside a groupingBy, producing a flat collection per group instead of a nested one.

// dept → flat set of all tags of products (hypothetical: employees carry skills)
// Here: category → flat unique set of all product tags in that category
Map<String, Set<String>> tagsByCategory = products.stream()
    .collect(groupingBy(Product::category,
             flatMapping(p -> p.tags().stream(), toSet())));
// Books       → [tech, education, fiction, leisure]
// Clothing    → [casual, summer, denim]
// Electronics → [tech, premium, work]

// without flatMapping you'd need a second stream pass:
// groupingBy → List<List<String>> → then flatMap — flatMapping does it in one shot

13.2 · toUnmodifiableList / Set / Map Java 10

// guaranteed unmodifiable result — throws UnsupportedOperationException on add/put
List<String> immutableNames = emps.stream()
    .map(Employee::name)
    .collect(toUnmodifiableList());

Set<String> immutableDepts = emps.stream()
    .map(Employee::dept)
    .collect(toUnmodifiableSet());

Map<String, Double> immutableSalaries = emps.stream()
    .collect(toUnmodifiableMap(Employee::name, Employee::salary));
// all three: immutableNames.add("X") → UnsupportedOperationException

13.3 · Collectors.filtering Java 9 — scoped filter inside a downstream

Unlike stream().filter() which applies before grouping, filtering inside a downstream applies per group — empty groups still appear in the result.

// groupingBy dept, but only count ACTIVE employees per dept
// filter().groupingBy → missing-dept problem: inactive depts disappear entirely
Map<String, Long> activeCountWrong = emps.stream()
    .filter(Employee::active)               // inactive depts silently vanish
    .collect(groupingBy(Employee::dept, counting()));
// {Engineering=2, HR=2, Sales=1}   — Sales only shows 1 (Dee is inactive)

// filtering() downstream: all depts present, count reflects active only
Map<String, Long> activeCountRight = emps.stream()
    .collect(groupingBy(Employee::dept,
             filtering(Employee::active, counting())));
// {Engineering=2, HR=2, Sales=1}  — same here because Dee is in Sales
// But if ALL Sales were inactive, first approach drops "Sales" key entirely;
// filtering() keeps it with count=0

13.4 · counting() vs .count() — when they differ

// .count() — terminal op, simplest
long n1 = emps.stream().filter(Employee::active).count();   // 5

// counting() — downstream Collector; use INSIDE collect() only
long n2 = emps.stream().collect(filtering(Employee::active, counting()));   // 5

// in a groupingBy, counting() is the right tool (count() can't be a downstream)
Map<String, Long> perDept = emps.stream()
    .collect(groupingBy(Employee::dept, counting()));
// {Engineering=3, HR=2, Sales=2}

13.5 · groupingByConcurrent — parallel-friendly grouping

// on a very large list with parallelStream(), groupingByConcurrent avoids
// merging partial maps — it accumulates directly into a shared ConcurrentMap
ConcurrentMap<String, List<Employee>> concurrentByDept = emps.parallelStream()
    .collect(groupingByConcurrent(Employee::dept));
// same result as groupingBy but uses a ConcurrentHashMap underneath —
// encounter order within each group's list is NOT guaranteed
groupingByConcurrent is unordered — elements within each group's list may appear in any order. Use groupingBy when order matters.

14 · Short-circuit & matching terminals

These terminals stop the pipeline as soon as the answer is known — they don't consume the whole stream.

14.1 · anyMatch / allMatch / noneMatch

// anyMatch: stops at first TRUE element
boolean anyInactive  = emps.stream().anyMatch(e -> !e.active());           // true (Dee)
boolean anyOver200k  = emps.stream().anyMatch(e -> e.salary() > 200_000); // false

// allMatch: stops at first FALSE element
boolean allActive    = emps.stream().allMatch(Employee::active);            // false
boolean allPositive  = orders.stream().allMatch(o -> o.amount() > 0);      // true

// noneMatch: stops at first TRUE element
boolean noneNegative = orders.stream().noneMatch(o -> o.amount() < 0);     // true
boolean noneEngInSF  = emps.stream()
    .filter(e -> e.dept().equals("Engineering"))
    .noneMatch(e -> e.city().equals("SF"));                                 // false (Bob)

// compose with Predicate for reuse
Predicate<Employee> highPaid = e -> e.salary() >= 100_000;
boolean deptHasHighPaid = emps.stream()
    .filter(e -> e.dept().equals("Engineering"))
    .anyMatch(highPaid);   // true

14.2 · findFirst vs findAny

// findFirst — deterministic, respects encounter order
Optional<Employee> first = emps.stream()
    .filter(e -> e.dept().equals("HR"))
    .findFirst();
// Optional[Eve]   — always Eve (first HR employee in list order)

// findAny — no order guarantee; parallel streams may return any matching element
Optional<Employee> any = emps.parallelStream()
    .filter(e -> e.dept().equals("HR"))
    .findAny();
// Optional[Eve] or Optional[Frank] — non-deterministic under parallel()

// safe consumption pattern
emps.stream()
    .filter(e -> e.salary() > 100_000)
    .findFirst()
    .ifPresent(e -> System.out.println("First 100k+: " + e.name()));
// First 100k+: Bob

14.3 · min / max as terminal ops

// cheapest product
Optional<Product> cheapest = products.stream()
    .min(Comparator.comparingDouble(Product::price));
// Optional[Novel(14.99)]

// most expensive order per customer (using groupingBy + maxBy)
Map<String, Optional<Order>> biggestOrderPerCustomer = orders.stream()
    .collect(groupingBy(Order::customerId,
             maxBy(Comparator.comparingDouble(Order::amount))));
// C1 → O1($1200), C2 → O6($3100), C3 → O6... wait — C3 has O6($3100)

// unwrapped version
Map<String, Order> biggestUnwrapped = orders.stream()
    .collect(groupingBy(Order::customerId,
             collectingAndThen(
                 maxBy(Comparator.comparingDouble(Order::amount)),
                 Optional::get)));
// C1 → O1(1200), C2 → O6(3100), C3 → O6(3100)

14.4 · toArray — when you need an array, not a List

// Object[] (untyped)
Object[] arr = emps.stream().map(Employee::name).toArray();

// typed array via generator
String[] names = emps.stream().map(Employee::name).toArray(String[]::new);

// primitive array
double[] salaries = emps.stream().mapToDouble(Employee::salary).toArray();
// [95000.0, 110000.0, 62000.0, 68000.0, 74000.0, 71000.0, 105000.0]

14.5 · forEachOrdered — guaranteed order in parallel streams

// forEach in a parallel stream may print in any order
emps.parallelStream().forEach(e -> System.out.println(e.name()));  // random order

// forEachOrdered preserves encounter order, even in parallel
emps.parallelStream().forEachOrdered(e -> System.out.println(e.name()));
// Ada, Bob, Cy, Dee, Eve, Frank, Grace  — always in list order
forEachOrdered negates most of the parallelism benefit — use toList() + iterate the list if you need order.
