Private interface methodsJava 9Language
Old
interface Notifier {
    default void notifyInfo(String msg) {
        send("[INFO] " + timestamp() + msg);
    }
    default void notifyWarn(String msg) {
        send("[WARN] " + timestamp() + msg);
    }
    // No way to share formatting logic
    // without making it part of the public API
}
Modern
interface Notifier {
    private String prefix(String level) {
        return "[" + level + "] " + timestamp();
    }
    default void notifyInfo(String msg) {
        send(prefix("INFO") + msg);
    }
    default void notifyWarn(String msg) {
        send(prefix("WARN") + msg);
    }
}

JEP 213 — private methods keep helper logic inside the interface without exposing it as part of the contract.

Try-with-resources: effectively-final variableJava 9Language
Old
InputStream  in  = new FileInputStream("a.txt");
OutputStream out = new FileOutputStream("b.txt");
// Must re-declare in the try() header
try (InputStream i = in; OutputStream o = out) {
    i.transferTo(o);
}
Modern

// Reference effectively-final vars directly

    in.transferTo(out);
}

Variables must be effectively final (never re-assigned after the try statement). Eliminates the need for redundant alias declarations.

StackWalker — lazy stack inspectionJava 9Tooling / JVM
Old
// Allocates the entire stack trace array immediately

    Thread.currentThread().getStackTrace();
String callerClass = frames[2].getClassName();
Modern
// Lazy — walks only as many frames as needed

    .walk(frames -> frames
        .skip(1).findFirst()
        .map(StackWalker.StackFrame::getClassName)
        .orElse("unknown"));
// Also: StackWalker.getInstance(RETAIN_CLASS_REFERENCE)

JEP 259 — StackWalker is significantly faster when you only need the top N frames, and enables filtering/mapping without allocating the full array.
